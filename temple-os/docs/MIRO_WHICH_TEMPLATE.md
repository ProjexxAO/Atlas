# Which Miro Template Should I Use?

Quick guide to choose the right Temple Architecture template for your needs.

---

## 🎯 QUICK DECISION TREE

**How much time do you have?**

### ⚡ 5 Minutes - Quick Brainstorm
→ Use: **MIRO_CHECKLIST.md** (Super Minimal version)
- Copy the bottom section (6 lines)
- Paste into ONE Miro text box
- Fill in blanks
- Perfect for: Initial idea capture, team brainstorm kickoff

### ⏱️ 30 Minutes - Sprint Planning
→ Use: **MIRO_CHECKLIST.md** (Full version)
- Copy the full checklist
- Paste into ONE Miro text box
- Work through each section
- Perfect for: Sprint planning, MVP scoping, quick architecture review

### 🕐 2 Hours - Detailed Planning
→ Use: **MIRO_QUICK_TEMPLATE.md**
- Create sticky notes/cards for each section
- Use the 24 pre-written cards
- Organize into frames by color
- Perfect for: New feature planning, architecture review, team workshops

### 📅 Half Day - Complete Architecture
→ Use: **MIRO_TEMPLATE.md**
- Full 15-step framework
- Use as section headers in Miro
- Create detailed cards under each
- Perfect for: New product planning, major refactor, architecture documentation

### 🏗️ Ongoing Project - Living Documentation
→ Use: **MIRO_BOARD_LAYOUT.md**
- Choose one of 3 layout options
- Set up as permanent project board
- Update as project evolves
- Perfect for: Active development, team collaboration, stakeholder updates

## 👥 BY TEAM SIZE

### Solo Developer
- **Quick Checklist** for personal projects
- **Quick Template** for client work
- Keep it simple, iterate fast

### Small Team (2-5)
- **Quick Template** for features
- **Full Template** for new products
- **Dashboard Layout** for active projects

### Large Team (6+)
- **Full Template** mandatory for all projects
- **Dashboard Layout** for visibility
- Multiple boards for different workstreams

---

## 🎨 BY PROJECT TYPE

### MVP / Prototype
→ **MIRO_CHECKLIST.md** (30 min version)
- Speed over completeness
- Just enough architecture
- Iterate quickly

### Production App
→ **MIRO_TEMPLATE.md** (Full framework)
- Complete all 15 steps
- Document all decisions
- Plan for scale

### Enterprise System
→ **MIRO_TEMPLATE.md** + **MIRO_BOARD_LAYOUT.md**
- Full framework + multiple boards
- Extensive documentation
- Stakeholder reviews

### Internal Tool
→ **MIRO_QUICK_TEMPLATE.md**
- Balanced approach
- Good documentation
- Not over-engineered

## 📊 BY USE CASE

### Planning a New Feature
1. Start with **MIRO_CHECKLIST.md** (5 min version)
2. If complex, upgrade to **MIRO_QUICK_TEMPLATE.md**
3. Create detailed cards for implementation

### Architecture Review
1. Use **MIRO_BOARD_LAYOUT.md** (Dashboard layout)
2. Fill in current state
3. Identify gaps and improvements

### Team Workshop
1. Use **MIRO_QUICK_TEMPLATE.md**
2. Work through as a group
3. Assign owners to each card

### Stakeholder Presentation
1. Use **MIRO_BOARD_LAYOUT.md** (Vertical Temple layout)
2. Most visual and clear
3. Hide technical details

### Developer Onboarding
1. Use existing **MIRO_BOARD_LAYOUT.md** (Dashboard)
2. Walk through each section
3. Answer questions inline

## 🔄 TYPICAL PROGRESSION

Most projects follow this pattern:

```
Day 1: Brainstorm
→ MIRO_CHECKLIST.md (5 min version)
→ "Do we want to build this?"

Day 2: Initial Planning
→ MIRO_QUICK_TEMPLATE.md (24 cards)
→ "What's the basic architecture?"

Week 1: Detailed Design
→ MIRO_TEMPLATE.md (Full framework)
→ "How do we build this?"

Week 2+: Active Development
→ MIRO_BOARD_LAYOUT.md (Dashboard)
→ "What's our status?"

Launch: Documentation
→ Export Miro board as PDF
→ Update README with decisions
```

## 💡 PRO TIPS

### Tip 1: Start Small, Expand
- Begin with checklist
- If project grows, copy to detailed template
- Don't over-engineer early

### Tip 2: Save as Template
- Once you customize a template, save it in Miro
- Name it: "Temple - [Your Org] - [Use Case]"
- Reuse for similar projects

### Tip 3: Combine Templates
- Use checklist for quick reference
- Use full template for documentation
- Keep both on same board

### Tip 4: Color Code Consistently
Always use same colors:
- 🔵 Outer Court
- 🟢 Inner Court
- 🟡 Priests
- 🟣 Sanctuary
- 🔴 Ark
- 🔵 River (Teal)
- 🟠 Memory

### Tip 5: Link Everything
- Link Miro to GitHub issues
- Link to Figma designs
- Link to API docs
- Central source of truth

## ❓ FAQ

**Q: Can I modify these templates?**
A: Absolutely! They're starting points. Adapt to your needs.

**Q: Do I need to fill out every section?**
A: No. Skip sections that don't apply. The "7 Questions" are mandatory though.

**Q: Can I use this for non-Temple architecture?**
A: Yes! The framework works for any system. Just rename the chambers.

**Q: How do I share with stakeholders?**
A: Export as PDF, or share Miro board with view-only access.

**Q: Can I use this for mobile apps?**
A: Yes! Priests might be "ViewModel", "Repository", etc. Same pattern.

## 🚀 GETTING STARTED (First Time)

1. Open Miro
2. Create new board
3. Copy **MIRO_CHECKLIST.md** (full version)
4. Paste into Miro text box
5. Set font: Monospace, size 12
6. Fill it out (30 min)
7. If project is complex:
   - Create new board
   - Use **MIRO_QUICK_TEMPLATE.md**
   - Create 24 cards
   - Organize into colored frames

**You're done!** 🎉

Save as template and reuse for next project.
